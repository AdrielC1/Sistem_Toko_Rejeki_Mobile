## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Mobile Client ↔ LAN / Tunnel Server URL | User-configured HTTP/HTTPS URL determines where credentials and session cookies are sent |
| Server `Set-Cookie` ↔ Device `SecureStore` / `kv-store` | `pos_session` HMAC token and user snapshot cross from `expo/fetch` into OS Keychain/Keystore |
| Stale Async `/me` Response ↔ Active Session State | Overlapping network responses could race with login/logout transitions |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-02 | Tampering | `serverConfig.ts` | high | mitigate | Enforce `http:`/`https:` scheme and valid hostname validation via `zod` in `normalizeServerUrl` and trim accidental trailing slashes or `/api` suffixes before network requests |
| T-01-03 | Information Disclosure | `cookieParser.ts`, `secureStorage.ts`, `authApi.ts` | high | mitigate | Store `pos_session` and `AuthSessionUser` strictly in `expo-secure-store` (omitting `requireAuthentication`), place larger `storeLogo` settings in `kv-store`, log only `{ captured, length }` in `__DEV__`, and call `clearSessionToken()` if `token === null` on `200` login |
| T-01-04 | Denial of Service | `apiClient.ts` | medium | mitigate | Separate `401` and `/api/auth/me` `403` from feature `403`/`5xx`/network failures and guard async revocations with monotonic `authEpoch` so transient errors never lock out offline cashiers |
| T-01-SC | Tampering | `package.json` | low | mitigate | Zero new packages added in Plan `01-02`; relies solely on dependencies vetted in Plan `01-01` |
